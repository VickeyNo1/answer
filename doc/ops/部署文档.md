## 一、架构与网络

**双机分离架构（VPC 对等，私网互通，可用区广州A）：**

| 角色 | 公网 IP | 私网 IP | 系统 | 运行组件 |
|------|---------|---------|------|----------|
| **机器A**（数据服务器） | `8.134.97.196` | `172.22.207.228` | Alibaba Cloud Linux 3 | MySQL 8.4 + 向量化知识库 + 知识库检索服务 `:8100` |
| **机器B**（应用服务器） | `8.148.219.179` | `172.17.240.44` | Alibaba Cloud Linux 2 | Nginx + Next.js(3000) + FastAPI(8000) |

**流量路径（生产）：**

```
浏览器 ──HTTP:80──> 机器B Nginx ┬─ /api/ ─> 127.0.0.1:8000 FastAPI ─┬─私网─> 机器A MySQL 172.22.207.228:3306
                                └─ /     ─> 127.0.0.1:3000 Next.js   └─私网─> 机器A 知识库 172.22.207.228:8100
```

**关键约定：**
- 生产环境机器B **走私网** `172.22.207.228` 访问机器A（MySQL 与知识库）；开发环境才用机器A 公网 `8.134.97.196`。
- 机器A 的 MySQL 3306 仅对机器B 私网与本机放行；知识库 `:8100` 仅私网暴露。
- 机器B 只对公网开放 **80** 端口；后端 8000 / 前端 3000 仅监听 `127.0.0.1`，由 Nginx 统一反代（同源，无 CORS）。

## 二、部署方式

- **代码上机**：GitHub（`git@github.com:VickeyNo1/answer.git`）→ 机器B `git clone/pull`。
- **进程管理**：systemd（后端 `answer-backend`、前端 `answer-frontend`），开机自启、崩溃自拉起。
- **反向代理**：Nginx。
- **部署产物**（仓库 `deploy/` 目录）：

| 文件 | 用途 | 目标位置 |
|------|------|----------|
| `deploy/answer-backend.service` | 后端 systemd 单元（uvicorn） | `/etc/systemd/system/` |
| `deploy/answer-frontend.service` | 前端 systemd 单元（next start） | `/etc/systemd/system/` |
| `deploy/nginx-answer.conf` | Nginx 反代（含 SSE 关闭缓冲） | `/etc/nginx/conf.d/answer.conf` |
| `deploy/bootstrap.sh` | 机器B 首次环境初始化（装 nginx/Node20/uv + 拉码） | 仓库内执行 |
| `deploy/deploy.sh` | 幂等部署/更新（拉码→建表→构建→重启→健康检查） | 仓库内执行 |

> `deploy/*.sh` 由 `.gitattributes` 强制 LF 换行，避免在 Linux 上出现 `$'\r'` 报错。

## 四、首次部署（机器B，root 执行，仅一次）

### 步骤 0：本地推送代码（在你自己的终端）

```powershell
cd d:\code\answer
git push origin main
```

### 步骤 1：拉代码 + 初始化环境

```bash
yum install -y git
git clone git@github.com:VickeyNo1/answer.git /opt/answer
# 若机器B 未配 GitHub SSH key，改用 https：
#   git clone https://github.com/VickeyNo1/answer.git /opt/answer

bash /opt/answer/deploy/bootstrap.sh
```

`bootstrap.sh` 会安装：`git`、`nginx`、Node.js 20（NodeSource）、`uv`（自带管理 Python 3.11），并确保代码就位。

### 步骤 2：创建配置文件（含密钥，不入库）

**① 后端 `/opt/answer/backend/.env`**（生产走**私网** `172.22.207.228`）：
```ini
DASHSCOPE_API_KEY=<通义千问 API Key>
JWT_SECRET_KEY=<随机长串，生产务必更换>
JWT_ALGORITHM=HS256
JWT_EXPIRE_HOURS=24
MYSQL_HOST=172.22.207.228
MYSQL_PORT=3306
MYSQL_USER=answer
MYSQL_PASSWORD=<机器A MySQL 密码>
MYSQL_DB=answer
KB_BASE_URL=http://172.22.207.228:8100
# 必须与机器A知识库服务配置的 token 一致（在其项目 .env 的 KB_TOKEN 中查看）；
# 留空或不一致时所有检索被 4010 拒绝，对话将始终显示"未参考知识库资料"
KB_TOKEN=<机器A知识库服务的 token>
KB_TIMEOUT=10
CORS_ORIGINS=http://8.148.219.179
CHAT_MODEL=qwen3.6-flash
```

**② 前端 `/opt/answer/frontend/.env.production`**（构建时注入浏览器访问的后端地址）：
```ini
NEXT_PUBLIC_API_URL=http://8.148.219.179
```

> 若后续启用域名，把 `CORS_ORIGINS` 与 `NEXT_PUBLIC_API_URL` 改为 `http(s)://域名`，并重跑步骤五构建。

### 步骤 3：安装 systemd 服务与 Nginx

```bash
cp /opt/answer/deploy/answer-backend.service  /etc/systemd/system/
cp /opt/answer/deploy/answer-frontend.service /etc/systemd/system/
cp /opt/answer/deploy/nginx-answer.conf       /etc/nginx/conf.d/answer.conf
systemctl daemon-reload
systemctl enable answer-backend answer-frontend nginx
nginx -t
```

### 步骤 4：构建并启动

```bash
bash /opt/answer/deploy/deploy.sh
```

流程：`git pull` → 后端 `uv sync` + `seed.py`（建库建表 + 写入管理员/默认模型，幂等）→ 前端 `npm ci` + `npm run build` → 重启三个服务 → 健康检查。

完成后访问 **http://8.148.219.179/**，默认管理员 `admin / admin123`（首次登录后请改密）。

## 六、排障速查

```bash
# 服务状态
systemctl status answer-backend answer-frontend nginx

# 日志（后端故障多为连不上 MySQL）
journalctl -u answer-backend  -n 80 --no-pager
journalctl -u answer-frontend -n 80 --no-pager

# 本机健康检查
curl -s http://127.0.0.1:8000/api/health                          # 后端 -> {"status":"ok","mysql":"ok","kb":"ok"}
curl -s http://127.0.0.1:3000 -o /dev/null -w "%{http_code}\n"     # 前端 -> 200
```

> **`/api/health` 语义（v4.0）**：返回 `status`/`mysql`/`kb` 三字段，HTTP 始终 200。`status="degraded"` 表示 MySQL 或知识库依赖异常（对应字段为 `fail`），需人工排查，**不代表部署成功**（`deploy.sh` 仅当 `status="ok"` 才判定部署成功）；如只需进程存活探测，不应依赖此接口的 degraded 语义（可改用端口/进程检查）。

| 现象 | 排查方向 |
|------|----------|
| 后端起不来 / 502 | 看 `journalctl -u answer-backend`；多为 `.env` 的 MySQL 私网连接失败（检查步骤三前置项 2/4） |
| 前端 502 / 白屏 | `answer-frontend` 是否 running；`npm run build` 是否成功 |
| 登录/接口跨域报错 | `.env` 的 `CORS_ORIGINS` 是否与访问域名一致；确认走的是 Nginx 同源入口 |
| 对话不流式（整段才出） | 确认 Nginx 用了本仓库的 `nginx-answer.conf`（`/api/` 段有 `proxy_buffering off`） |
| 回答无知识点/未检索 | 机器B→A `:8100` 是否私网可达；不可达时为正常降级（大模型直答） |
| `deploy.sh` 报 `$'\r'` | 该文件被改成 CRLF；确认 `.gitattributes` 生效或 `sed -i 's/\r$//' deploy/*.sh` |

## B2 考试核心：创建/暂存/交卷/查询（学生端 6 接口，~4 天）

### 2.1 新模块 `app/exam/`（router.py + store.py + judger.py）

新路由**必须** `Depends(get_db)`（AGENTS §6 + 设计 §3.3 技术债约定）；仅判卷后台任务用 `get_db_ctx()`。

### 2.2 schema（`app/models.py`）

- `ExamCreateRequest`（subject/chapter_ids/counts）、`ExamCreateResponse`、`ExamAnswersSaveRequest`（answers: [{seq, content}]）、`ExamSubmitResponse`、`ExamListItem`、`ExamDetailResponse`（含 answers + mastery）、`AdminExamListItem`、`AdminScoreUpdateRequest`（score/reason）

### 2.3 `store.py` 数据访问

- `create_exam`：**「每人仅 1 张 ongoing」应用层校验**（设计 §4.2 定调）——`SELECT id FROM exams WHERE user_id=%s AND status='ongoing'`，校验+插入包在**模块级 `threading.Lock`** 内防并发穿透；存在则 409 返回未完成试卷 id
  - 调 `draw_exam` 抽题 → 逐题落 `exam_answers`（seq 从 1 起，`question_snapshot` 存题目全量 JSON，**含参考答案/解析**，防知识库改题错位）
  - 题型满分固定值：单选 1 / 多选 2 / 计算 10 / 综合 15（常量表放 `judger.py`）
  - 创卷响应**剔除**参考答案与解析（answer/explanation 不出快照）
- `save_answers`：按 `(exam_id, seq)` 批量 UPDATE `student_answer`；仅 `status='ongoing'` 且本人试卷可暂存，否则 403/409
- `list_exams` / `get_exam_detail`：详情仅 `graded` 后返回 answer/explanation/mastery；`ongoing/grading` 只回作答进度与状态
- 掌握度归因 `compute_mastery(answers) -> dict`（放 store.py）：严格按设计 §4.5 算式——kp 掌握度 = Σ得分/Σ满分（一题多 kp 不摊分）；章节掌握度按满分加权；weak = rate<0.6 升序。章节 id 取 kp_id 前缀（如 `ACC-03-02-01` → `ACC-03`）

### 2.4 `router.py` 学生端 6 接口（请求/响应体照设计 §4.6）

| 接口 | 关键行为 |
|------|---------|
| `POST /api/exams` | 校验 subject 枚举（非法回退 DEFAULT_SUBJECT）、counts 至少 1 题；抽题失败 502 |
| `PUT /api/exams/{id}/answers` | 暂存，可多次 |
| `POST /api/exams/{id}/submit` | 客观题即时判分 → 有主观题置 `grading` 并提交后台判卷，无主观题直接 `graded` 汇总总分；响应含 `objective_score`/`pending_subjective`；重复交卷 409 |
| `GET /api/exams` | 我的考试列表（倒序） |
| `GET /api/exams/{id}` | 成绩单详情（归属校验，非本人 403） |
| `POST /api/exams/{id}/answers/{seq}/dispute` | 仅主观题且 `graded` 后可标 `disputed=1` |

- `main.py` 注册 `exam_router`

**B2 验收**：mock 抽题下，创建→暂存→交卷（纯客观题）→详情全链路单测通过；ongoing 唯一、归属校验、409/403/502 边界用例齐。

## B3 判卷引擎 + 异步执行（~4 天）

### 3.1 `judger.py` 客观题判分

- 单选：与参考答案全等得满分；多选：选项集合完全一致得满分否则 0（**不做半对给分**）；作答为空记 0 分
- 判分依据一律读 `question_snapshot`（不回查知识库）

### 3.2 `judger.py` 主观题 LLM 判卷（设计 §4.3/§4.4）

- 模块级单例 `ThreadPoolExecutor(max_workers=2)`（**M3 画像总结复用此池**，命名中性如 `_bg_executor`）
- 交卷接口落库后 `submit()` 提交任务立即返回；任务内逐题：
  - prompt 输入 = 题干 + materials + 参考答案 + 解析 + 学生作答；要求只输出 JSON `{"score_rate": 0.7, "reason": "…"}`
  - 模型用 `get_active_model()`；`score = full_score × score_rate` 四舍五入到 0.5；score_rate 越界钳到 [0,1]
  - 单题失败重试 1 次，仍失败记 `score=NULL` + `llm_reason='[判卷失败] …'`，**试卷仍置 graded**
  - 落库用 `with get_db_ctx()`（后台线程无请求上下文）
- 全部题目完成后：汇总 `obtained_score`（NULL 分题按 0 计入总分）、置 `status='graded'`、写 `submitted_at` 不变
- token 记账：每次 LLM 调用 `record_usage(..., task_type='exam')`，`conversation_id=NULL`

### 3.3 学生端感知

- 无推送：成绩单页 `status='grading'` 时前端每 5s 轮询 `GET /api/exams/{id}`（B4 前端实现）

**B3 验收**：客观判分规则单测（多选半对 0 分等）；掌握度算式单测（构造已知作答核对数值）；LLM 判卷用 mock dashscope 单测（成功/重试成功/两次失败记 NULL/总分汇总）；真实 LLM 用 3 道样例题（满分答案/半对/胡写）人工验证 score_rate 区分度。

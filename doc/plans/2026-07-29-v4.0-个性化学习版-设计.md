# v4.0 个性化学习版 · 设计文档

> 状态：设计已确认（2026-07-29 头脑风暴定稿）｜ 上一版本：v3.0（Function Calling + 外部知识库，已上线）
> 设计原则：**重后端、轻前端**（前端尽可能简单简洁）；所有新功能为将来收费模块预埋权益字段。

---

## 1. 背景与目标

5-10 名真实学生即将进场试点。本版本要同时达成四个试点目标：

| 目标 | 对应功能 |
|------|---------|
| 收集答案质量反馈 | 消息级点赞/点踩 + 理由 |
| 验证知识库检索效果 | 检索日志落库 + 空结果率/降级率报表 |
| 验证产品粘性 | 引用溯源、追问建议、学生记忆、考试与错题本、移动端自适应 |
| 向使用方汇报 | 管理后台报表面板（检索质量/反馈明细/高频知识点） |

规模假设：≤10 并发用户，因此**不做**分布式限流、消息队列中间件、费用预算系统（YAGNI）；并发防护用进程内信号量即可。

## 2. 里程碑总览（三批独立上线）

| 里程碑 | 内容 | 周期 | 依赖 |
|--------|------|------|------|
| **M1 试点底座** | 反馈收集、检索可观测、引用卡片+追问建议、并发闸门+每日配额、权益字段预埋、管理报表、学生自助改密码、移动端自适应、安全收尾 | ~2 周 | 无。**学生 M1 后即可进场** |
| **M2 考试系统** | 知识库抽题接口（知识库侧自维护）、试卷生成/作答/交卷、客观题程序判分+主观题 LLM 异步判卷、掌握度归因 | ~2-3 周 | 知识库侧 `/kb/exam/draw` |
| **M3 学生记忆** | 错题本、薄弱点统计、学习风格画像、记忆注入对话、管理端记忆开关生效 | ~1-2 周 | M2 的考试错题数据 |

### 3.3 聊天链路改造（`app/chat/router.py` + `qwen_service.py` + `kb/client.py`）

按请求处理顺序：

1. **配额校验**：`SELECT COUNT(*) FROM messages WHERE role='user' AND created_at >= CURDATE()`（按 user 关联会话计数）≥ 生效上限 → HTTP 429 `{"detail": "今日提问次数已用完（20/20），明天再来吧"}`。
2. **单人串行**：进程内 `set[user_id]` 记录进行中的对话，重复提问 → 429 `{"detail": "上一条回答还在进行中"}`。
3. **并发闸门**：全局 `asyncio.Semaphore(chat_concurrency)`；拿不到锁时进入等待，等待人数 > `chat_queue_size` → 429「当前提问人数较多」；等待期间通过 SSE 下发 `queue` 事件报队位。
4. **检索日志**：`kb/client.py` 每次调用后写 `kb_search_logs`（含失败情形）；同时日志分级：`logger.info`（ok/empty）、`logger.warning`（timeout/http_error/code_error）、`logger.error`（degraded）。
5. **降级话术分档**：检索服务不可用（degraded）→ 答案尾部附「⚠️ 知识库暂时不可用，本回答未经教材核对」；检索成功但空结果（empty）→ 附「知识库中未检索到直接相关内容」。
6. **引用卡片**：检索成功后，SSE 新事件 `kb_refs` 下发命中片段摘要（编号/章节/标题/content 前 100 字），前端渲染为可展开卡片。
7. **追问建议**：二轮回答的 system prompt 追加指令，要求在答案末尾以约定分隔符输出 3 条追问；后端解析剥离，以 SSE `suggestions` 事件下发（解析失败则无此事件，不影响正文）。

**SSE 事件全集（v4.0）**：`start`、`queue`（新）、`kb_search`、`kb_refs`（新）、`kp_ids`、`delta`、`suggestions`（新）、`done`、`error`。

## 4. M2 考试系统

### 4.1 知识库侧新接口（知识库自维护，后端只消费）

```
POST /kb/exam/draw    （Header: X-KB-Token，复用现有认证）
请求: { "subject": "cpa_acc",
       "chapter_ids": ["ACC-01", "ACC-03"],      ← null 或缺省 = 全科目范围
       "counts": { "单选": 5, "多选": 3, "计算": 1, "综合": 1 } }
响应: { "code": 0, "questions": [ …与 /kb/search collection=questions 的 results 元素同构… ] }

```

- 随机性由知识库侧保证（同参数重复调用返回不同题组）。
- **后端降级策略：抽题失败不降级、直接报错**（考试没题就是办不成，如实返回 502「知识库暂时不可用，请稍后再试」）——与答疑链路的静默降级策略刻意不同。

### 4.3 判卷规则

- **客观题**（程序即时判）：单选全对得分；多选与参考答案完全一致得满分，否则 0 分（不做半对给分，避免规则争议）。
- **主观题**（LLM 异步判）：交卷后后台任务逐题调用当前激活模型：输入 = 题干+materials+参考答案+解析+学生作答，要求输出 JSON `{"score_rate": 0.7, "reason": "…"}`；`score = full_score × score_rate`（四舍五入到 0.5）。判卷 token 照常写入 `usage_logs`。
- 判卷期间 `exams.status='grading'`，全部完成后置 `graded` 并汇总 `obtained_score`；LLM 判卷失败的题记 0 分、`llm_reason='判卷失败，请联系管理员'`（可复判）。
- 学生对主观题可点「我有异议」→ `disputed=1`，管理员在反馈报表中可见。

### 4.4 掌握度归因算法（输出喂给 M3）

```
知识点掌握度 = Σ(该知识点关联题目的得分) / Σ(该知识点关联题目的满分)
  · 一题多知识点时，该题得分/满分同时计入每个知识点（不摊分）
章节掌握度 = 章内各知识点掌握度按关联题目满分加权平均
薄弱知识点 = 掌握度 < 60% 的知识点，按掌握度升序
```

### 5.3 记忆注入（token 硬预算 ≤300）

对话 system prompt 追加「学生情况」块，构成与裁剪顺序：

```
【学生情况】                                    ← 三项全空时整块不注入（与 v3.0 行为一致）
薄弱知识点: ACC-03-02-01 固定资产折旧(掌握40%,错3题); …   ← Top5，~120 token，永远保留
学习风格: 偏好分录示例讲解，概念辨析题易错。                ← ≤200字，~150 token，超预算第 2 个砍
最近考试: 07-25 CPA会计 68分。                            ← ~30 token，超预算第 1 个砍
```

### 5.4 开关逻辑（**控用不控记**）

- 生效值 = `users.memory_enabled ?? app_settings.memory_enabled_default`；
- 关闭时：不注入 prompt、不触发画像总结（省 token）、前端隐藏错题本入口；
- **数据照常积累**（错题照落、对话照存）——将来学生付费开通时历史数据即刻可用。

### 5.5 接口设计

#### `GET /api/wrong-questions` 🟢 错题本列表

```json
请求: ?subject=cpa_acc&chapter_id=ACC-03&mastered=0&page=1&page_size=20
响应: { "total": 12, "items": [ { "id": 1, "question_type": "单选", "stem": "…",
        "options": {…}, "wrong_count": 3, "mastered": 0, "last_wrong_at": "…",
        "knowledge_point_ids": ["ACC-03-02-01"] } ] }
```
- 记忆开关关闭时返回 403 `{"detail": "错题本功能未开通"}`。

#### `POST /api/wrong-questions/{id}/retry` 🟢 重练判分

```json
请求: { "answer": "B" }                    ← 主观题传文字
响应: { "correct": true, "correct_answer": "B", "explanation": "…", "mastered": 1 }
```
- 客观题程序判；主观题 LLM 判（score_rate ≥ 0.6 视为答对）；答对置 `mastered=1`，答错 `wrong_count+1`。

#### `GET /api/me/profile` 🟢 我的画像（透明可见）

```json
响应: { "style_profile": "偏好分录示例讲解…", "weak_kps": [ { "kp_id": "…", "rate": 0.4, "wrong_count": 3 } ],
        "recent_exam": { "subject": "cpa_acc", "score": 68, "date": "2026-07-25" },
        "memory_enabled": true }
```

### 5.6 画像总结任务

- 触发：每次对话完成后 `dialog_count_since_update += 1`，达到 `profile_update_interval` 时异步触发；
- 输入：最近 40 条消息（截断）；输出指令硬约束 ≤200 字，超长截断存储；
- 消耗计入 `usage_logs`（model_name 照实记录，报表可区分对话/判卷/画像用量——通过约定 conversation_id 为 NULL 时属系统任务）。

## 7. 测试计划

- **单测**（沿用 pytest + answer_test 库）：配额边界（第 N 次放行 / N+1 拒绝）、并发闸门（信号量满排队/队满 429）、单人串行、客观题判分规则（多选全对才给分）、掌握度归因（构造已知作答验证算式）、记忆注入裁剪顺序与 ≤300 token、开关"控用不控记"（关后错题照落库）、错题 UPSERT（重复错 wrong_count+1）。
- **E2E**：反馈提交→admin 列表可见；考试全流程（创建→暂存→交卷→客观题即时分→轮询到 graded）；记忆开/关下 system prompt 差异；改密码后旧 token 仍有效、新密码可登录。
- **移动端**：DevTools 375px 宽度下登录/对话/考试三页面核心操作可用（人工检查）。
- **LLM 判卷**：准备 3 道主观题样例（满分答案/半对答案/胡写答案），验证 score_rate 区分度。

## 8. 风险与假设

| 风险 | 缓解 |
|------|------|
| LLM 主观题判分误差 | 判分理由全程展示 + 学生异议标记 + 管理员可见复核清单 |
| 知识库 `/kb/exam/draw` 接口进度（用户自维护） | M2 开工前先定契约冻结；后端可先用 mock 数据开发 |
| 追问建议解析失败 | 约定分隔符解析失败则静默跳过，不影响正文 |
| 画像漂移/编造 | 覆盖式更新（不累积）、200 字硬限、学生可见（透明监督） |
| 429 学生体验 | 三档文案区分：排队中/队满/配额用尽，避免笼统报错 |

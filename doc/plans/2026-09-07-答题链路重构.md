# 答题链路重构（v4.1）· 2026-09-07

> 本文记录 v4.1 的**意图分流规则表**、**solve 三档命中判定**、**修复轮 8 个问题（§12）**与**批量评测工具及基准实测发现（§11）**，供后续调参与排查用。
> 代码位置：`backend/app/chat/intent.py`（分类）、`backend/app/chat/solver.py`（三档流水线）、`backend/app/admin/eval.py` + `backend/scripts/batch_eval.py`（批量评测）。

---

## 1. 为什么要改

学生的核心诉求是**问题目**——文字或拍照，**即使题库里没有一模一样的题，也必须给出解答**。
改之前做不到，原因不在模型，在链路设计缺了三块：

| 缺口 | 具体表现 | 后果 |
|------|---------|------|
| **完全不区分意图** | `qwen_service.py` 一个 `SYSTEM_PROMPT` 应付所有提问，全项目搜不到 intent/classify | 概念性问题与题目走同一条路，题目得不到题目该有的对待 |
| **检索完全交给模型自主决定** | `stream_chat` 第 1 轮把 `search_cpa_knowledge` 丢给模型，由它决定要不要检索、查哪个 collection | 拍照上传的题目默认被判成 `textbook`（教材），**题库 collection 根本不会被查** |
| **没有「命中/未命中」的概念** | 检索回来 5 条就拼 5 条，从不判断这 5 条里有没有学生问的那道题 | 「题库里有原题」与「题库里没有」在系统看来毫无区别；学生无从判断该不该信 |

顺带修掉一个 P0：`kb/prompt.py::_format_questions` 原先无条件把题库 `answer`/`explanation`
喂给大模型，直接违反 `doc/知识库对接文档.md` 早就写明的「先答题后判卷场景**务必剪裁**」——
考试模块遵了，聊天模块没遵。学生说「给我几道练习题」，模型大概率连答案一起端出来。

## 2. 意图三分类（纯规则，不加 LLM 调用）

`classify_intent(text, has_image) -> "solve" | "practice" | "consult"`

**判定顺序即优先级，不可调换：**

| 序 | 条件 | 结果 |
|----|------|------|
| 1 | `has_image` | **solve**（拍照直通） |
| 2 | 命中**强 solve 标记** | **solve** |
| 3 | 命中 **practice 标记** | **practice** |
| 4 | `len(text) >= 60` 且命中**弱 solve 证据** | **solve** |
| 5 | 其余 | **consult** |

### 强 solve 标记（第 2 步）

- 关键词：`怎么做` `怎么解` `怎么答` `如何解` `如何做` `求解` `算一下` `计算一下`
  `解答一下` `讲解一下` `答案是什么` `正确答案` `这道` `这个题` `那道` `该题` `本题`
  `此题` `上一题` `上面那道` `要求：` `已知：`
- 正则：`(编制|写出|做出|做).{0,12}分录`、`第\s*\d+\s*题`、`[（(]\s*[)）]`（选择题括号空位）、
  `(单选题|多选题|判断题|计算题|综合题|简答题|分析题)\s*[:：]`、
  `(下列|以下|下述).{0,50}?(的是|的有|正确|错误|不正确|不属于)`
- 选项行：`^\s*[A-D][.、．)）]` 出现 ≥2 次；或行内 `[A-D][.、．]` 出现 ≥3 次
  （学生常把选项粘在一行：`A.存货 B.厂房 C.设备 D.专利权`）

### practice 标记（第 3 步）

`练习题` `真题` `模拟题` `刷题` `考考我` `测一测` `测验` `布置`
`出几道/题` `来几道/题` `给我几道/题` `做几道/题` `出题`

### 弱 solve 证据（第 4 步，需长度 ≥60 才生效）

公司名 `甲公司|乙公司|丙公司|某公司|某企业|A公司|B公司`、金额 `万元|亿元|元/股`、
年份 `20×|20X|2×`、题型词 `单选题|多选题|判断题|计算题|综合题|简答题|分析题`

### 为什么第 2 步必须排在第 3 步之前

「**这道练习题怎么做**」同时含 practice 标记，但学生要的是**这道题的答案**，不是再要几道题。
强 solve 标记优先，才不会把求助误判成出题。

### 故意**没有**放进强标记的词（防误伤 consult）

| 词 | 为什么不放 |
|----|-----------|
| `判断` | 「如何**判断**融资租赁」是 consult |
| `单选` | 「**单选**和多选有什么区别」是 consult |
| `怎么算` | 「存货跌价准备**怎么算**」偏概念，交给第 4 步的长度门槛处理 |

题型词只在带冒号（`单选题：`）时算强标记，否则只算弱证据。

### 分类错了会怎样（敢用规则而不用 LLM 的理由）

- **solve 误判成 consult** → 退回 v4.0 的 Function Calling 路径，即**改造前的现状行为**，无损。
- **consult 误判成 solve** → 走三档检索阶梯：题库检索空 → 教材检索 → 照常给出解答，
  只是多附一句「未找到原题」标注。**答案依然正确**，仅多一次检索开销。

两个方向都是**优雅降级**，不存在答不出来的情况。所以分类器不必追求准确率，规则足矣。

> **回归锚点**：`"存货怎么计价？"` 必须判为 **consult**（`test_intent.py` 与
> `test_chat_sse.py::test_consult_intent_keeps_legacy_path` 各守一处）。
> 它一旦被判成 solve，`test_chat_sse.py::test_chat_triggers_kb_search` 就会挂。

## 3. solve 三档命中判定

solve 意图**绕过 Function Calling 第 1 轮**，改为后端确定性执行检索阶梯，只做**一次**流式生成。

> 这不是能力削减：改造前 solve 类问题要花 2 次 LLM 调用（第 1 轮决定检索 + 第 2 轮作答），
> 新链路是 1 次校验 + 1 次作答，**调用次数不变**，但检索行为从「模型心情」变成「确定发生」，
> 且 `questions` collection 保证被查到。

| 档 | 触发条件 | 检索动作 | 喂给模型的题库内容 | 末尾标注 |
|----|---------|---------|------------------|---------|
| **exact**<br>原题命中 | questions 有结果 **且** LLM 校验 `same=true` 且 index 有效 | 仅 questions `top_k=3`，**跳过教材检索**（快路径） | 命中题**含** answer/explanation | `✅ 本题已在题库中找到原题…` |
| **similar**<br>相似题 | questions 有结果但校验 `same=false`、**index 越界**、或**校验失败** | questions `top_k=3` + textbook `top_k=5`；教材检索的 query 用**相似题的 `chapter`+题干/资料** | 相似题**含**答案，但标题行标明「相似但并非同一道」。**只喂 `relevant_indexes` 指认的那几道**；拿不到该信号（`None`）时才退回全量候选 | `📎 题库中未找到本题原题…` |
| **none**<br>无匹配 | questions 检索空，**或** 校验明确判定候选全不相关（`relevant_indexes=[]`，v4.1 修复轮新增的第二触发条件） | textbook `top_k=8` + `prefer="solve"` 定向排序 | 无（第二种情形下候选被丢弃，不注入噪声） | `⚠️ 知识库中未找到本题…` |

三档**全部产出完整解答**，区别只在依据强度与标注文案。

两个检索都返回 `None`（服务不可用）时，改用 `qwen_service.DEGRADED_SUFFIX`，**不叠加**档位标注。
exact 档本就不查教材，故其降级判定只看题库，不因 `t_data is None` 误报服务不可用。

### 为什么校验失败归 similar 而非 exact

**绝不在没有正向确认的情况下宣称「找到原题」**——这是本设计最重要的一条保守性约束。
误报 exact 会让学生拿着别人的答案去考试；漏报最多退到 similar，仍有相似题与教材可依。
代价不对称，故一律取保守。

### 为什么用 LLM 校验而不是 match_score 阈值

`doc/知识库对接文档.md` 明确写着 `score` 是「相关度分数（重排后），**仅用于排序，
不同请求间不可比**」。任何固定阈值方案都建立在错误前提上，**已否决**。

校验实现（`solver.verify_same_question`）：
- 模型 `llm_store.get_model_for("verify")`，**非流式**，`extra_body={"enable_thinking": False}`
- prompt 含本题原文 + 候选 top3（题干/选项/资料/子问，**不含答案解析**——校验用不上，省 token）
- 要求只输出 `{"same": true, "index": 1, "relevant_indexes": [1, 2], "reason": "…"}`
  ——**同一次调用既判同一性（定 exact）又指认哪几道值得作参考（相关性下限），零额外成本**
- 解析用 `find("{")` / `rfind("}")` 容错（与 `exam/judger.py::parse_judge_result` 同一模式）
- **任何异常/解析失败 → `same=False`**，`logger.warning` 记一条
- **只在 questions 检索有结果时才触发**——无结果直接判 none，不浪费这次调用
- 用量单独记账 `task_type="verify"`，try/except 包住；**不计入** `usage_acc`
  （校验模型可能与作答模型不同，混在一起算费用会错）

### 相关性下限：`relevant_indexes` 的 `None` 与 `[]` 不可合并（v4.1 修复轮）

检索服务**本身没有相关性下限**：乱码 query 也会返回满 `top_k` 条（实测 score 恒为
1.0/0.5/0.333 这类归一化排序分），所以「题库返回了结果」≠「题库里有相关的题」。
改造前这个缺口有两个后果：**none 档实际不可达**（只要有返回就一定落 similar），
以及**跨章节的无关题被当范例注入**，污染作答。只能由校验模型来判，`score` 阈值已否决。

三态必须严格区分，合并任两个都会出错：

| `relevant_indexes` | 含义 | 处理 |
|---|---|---|
| 非空数组 | 模型指认了值得参考的候选 | similar 档，**只注入被指认的那几道** |
| `[]` | 模型明确说没有一道与本题相关 | none 档，丢弃候选，教材定向检索独立推导 |
| `None` | **没拿到信号**：字段缺失 / 不是数组 / 序号全部越界（模型幻觉了序号）/ 调用抛异常 | 沿用旧的保守行为，全量候选注入 similar 档 |

`None` 与 `[]` 混为一谈的代价是二选一都错：当成 `[]` 会让每次校验超时都白白丢掉可用的
相似题参考；当成 `None` 会让 none 档继续不可达。越界序号的裁剪在调用方做（只有它知道
候选有几条），裁剪后为空按 `None` 处理——全越界说明信号本身不可用，而非「明确无相关」。

判定口径刻意**宽松**：同知识点但数据或问法不同的**应当列入**（这正是相似题的价值），
只有明显不同章节、不同业务的才排除。

### similar 档最大的失败模式

模型把相似题的数字抄进本题。防线有两条：
1. prompt 里的 `SIMILAR_BLOCK` 明写「**严禁照搬其数据、金额与答案**」，标题行也标明「并非同一道」
2. 教材检索的 query 改用**相似题自己的规范题干**而非 OCR 原文（干净、同话题，比噪声原文更准）

> 端到端验证时必须**逐字检查**有没有把相似题的金额抄进答案。

## 5. 检索 query 的取法（易踩坑）

```python
retrieval_query = (ocr_text or req.message).strip()[:1000]
```

**取 `ocr_text or req.message`，不取组合后的 `effective_message`**——
`"请解答\n\n【图片识别内容】\n…"` 这个前缀会污染向量检索。
长题干截断到 1000 字符（综合题带资料能上千字，过长会稀释语义）。

## 6. content_type 定向组装

知识库早就返回 `content_type` 字段（八种枚举），但改造前**全项目一次都没用过**，
`_format_textbook` 把 top_k 结果不分类型一股脑拼接。后果很具体：
一道分录题检索回 5 条可能全是 `theory`，模型读完仍不会写分录。

- **标注**：标签行加入中文类型名 —
  `theory 理论 / example 例题 / entry 分录 / table 表格 / formula 公式 / tip 提示 / faq 问答 / principle 原则`
  形如 `【资料1｜例题｜知识点 ACC-21-01-01｜第21章 租赁 · 第1节｜融资租赁的判断标准】`
- **定向排序**：`prefer="solve"` 时把 `example/entry/formula/table` 稳定排序到
  `theory/principle/faq/tip` 之前（同组内保持原 score 顺序，Python `sorted` 稳定）

### ⚠️ 必须兜底，否则现有测试集体挂掉

`content_type` 在现有测试假数据与线上老数据里**可能完全不存在**。
**必须用 `r.get("content_type")` 取值，缺失时归入「未分类」组排在最后，但绝不丢弃。**
若筛选逻辑丢弃缺字段条目，`test_kb.py` / `conftest.py::make_question()` /
`test_chat_sse.py::fake_search` 会全部拿到空结果而失败。

### 本轮不做

按 content_type 做**筛选删减**与 token 预算配额（只排序不删）——依赖完整意图数据积累，留下一轮。

## 7. 答案剪裁改为**默认剪裁**

```python
def format_results(data, prefer=None, include_answer=False, heading=None) -> str
```

**默认 `False`**，需要答案的调用方显式传 `True`。这是 safe-by-default：
即使意图分类把 practice 误判成 consult、走了老路径，答案也不会漏。

剪裁时在每题末尾附一行 `（参考答案与解析已省略，请先自行作答）`——
让模型知道答案存在但拿不到，从而引导学生先做，而不是模型自己编一个。

| 调用点 | `include_answer` |
|--------|-----------------|
| `solver.run_solve` exact 档 | `True`（就是学生问的那道题，必须给） |
| `solver.run_solve` similar 档 | `True`（相似题作范例，prompt 已严禁照搬） |
| `solver.run_practice` | `settings_store.get_bool("practice_reveal_answer")` → 默认 `False` |
| `qwen_service.stream_chat`（consult 老路径） | 同上，默认 `False` |

### 子问里藏着的答案也要剪

综合题的参考答案常分散在 `sub_questions` 对象里而顶层 `answer` 为 `null`。
只判顶层字段会漏掉「已省略」提示，模型便以为题库没有答案而自行编造。
故有 `_has_hidden_answer(r)`，且 `sub_question_text(sub, include_answer=False)` 默认不带子问答案。

### 管理端开关

`app_settings.practice_reveal_answer`（0/1，`BOOL_KEYS` 使其在 GET 响应里转 bool）。
价值：发现剪裁导致质量退化时，管理员**在线切换即可回退，不用发版**。

## 8. 分用途配模型（env 方案）

改造前 `llm_store.get_active_model()` 被对话/判卷/画像三处共用，加上本轮新增的 verify
与既有 OCR，五个用途的敏感度与调用量完全不同，共用必然是错的。

`config.py` 新增 `JUDGE_MODEL` / `PROFILE_MODEL` / `VERIFY_MODEL`，均默认 `""`
（**空串 = 跟随 active model**，不填就跟改造前一模一样）。
`llm/store.py::get_model_for(task_type)` 读对应字段，空则回退 `get_active_model()`。

| 用途 | 取值方式 | 建议档位 |
|------|---------|---------|
| 对话 | `get_active_model()`（后台控制，**不接 env 覆盖**） | 按后台配置 |
| 判卷 | `get_model_for("judge")` | **升到 plus 档**——只在交卷时跑、量小，但出错直接影响成绩、引发申诉、污染错题本与画像 |
| 画像 | `get_model_for("profile")` | 降 flash 档 |
| 校验 | `get_model_for("verify")` | 最便宜 flash 档（只输出一个 JSON） |
| OCR | `settings.VISION_MODEL` | `qwen-vl-plus`（vl-max 约两倍价，**降档前须人工验证转录完整性**） |

**建议档位待真实成本数据出来后再定**（见下条）。

## 9. OCR 记账（原先这笔开销完全没被记）

- `extract_question_text(image_base64, user_id=0, model_name=None)`，
  调用后以 `task_type="ocr"` 记账；读 usage **必须用 `getattr(resp, "usage", None)`**
- **`conversation_id` 只能传 `None`**：OCR 在建对话之前执行，此刻还没有 id。
  **不要为了记账把 OCR 挪到建对话之后**——那会破坏「OCR 失败不建对话、不落库、不扣配额」
- **前置**：`compute_cost()` 查不到模型时单价回退 `0.0`，而 `seed.py::DEFAULT_MODELS`
  原先**没有任何视觉模型** → 只补记账的话 tokens 会记但 `cost` 恒为 0。
  已补 `qwen-vl-max` / `qwen-vl-plus` 两条。

> ⚠️ **这两条视觉模型的单价是待核实占位值**，须到百炼控制台核对后修正
> （管理后台「大模型」Tab 可直接改，不必改代码重跑 seed）。

## 10. 已定但本轮不实现的决策（记录防丢失）

- **无匹配时不切强推理模型**：检索未命中 ≠ 题目难，是代理变量错配；且会计答疑瓶颈是知识不是推理。
  改为升级检索（提高 top_k、双 collection、content_type 定向、用相似题的 chapter 做二次检索）。
  **是否升模型等批量工具的专家评分数据出来再定**
- **相似题档绝不用题库答案判分、绝不写错题本**：`wrong_questions` 的
  `uk_user_question(user_id, question_id)` 唯一约束会把不同题 UPSERT 成同一行，
  污染 `wrong_count` 进而污染 M3 画像
- **换智谱**：GLM 已上架百炼，走同一 `base_url` `/compatible-mode/v1`，`create_client()` **零改动**；

### 11.1 落地形态

**本轮预埋的三样都用上了**：`match` 事件（结构化档位）、`include_answer` 开关；`get_model_for` 则是**这一轮才真正补完**——原先只有 chat/judge/profile/verify/ocr 五个用途，eval 用途是随本工具新增 `EVAL_MODEL` 才有的，§8 那句「eval 可独立配模型」在写下时其实是超前的。

### 11.3 意图分布实测：86.5% 会被判 consult —— 这就是 `--intent` 默认 `solve` 的依据

400 题过 `classify_intent`（纯文本）：**346 consult / 54 solve**。

原因很清楚：基准题面是书面陈述句（「资产的定义是什么？」「企业财务报告的主要目标是什么？」），既没有强 solve 标记（怎么做/这道题/要求：），长度也远不足弱 solve 证据的 60 字符门槛，公司名/万元/题型词也基本不出现。54 道判 solve 的几乎全靠「写出…分录」这一条正则捞回来的。

若按 `auto` 跑，346 题会走 consult 路径——没有三档命中、不碰题库，**评测不到答题能力**，等于四分之三的题目白跑。所以默认钉死 `solve`，`auto` 只作对照组量化这个偏差。

> ⚠️ **按 11.7 的治理约束，不据此调 `intent.py` 的规则表。** 真实学生提问与基准题面不是一个语体（学生会写「这道题怎么做」，基准写「判断下列处理是否正确」），拿基准去调规则等于把线上分类器往书面语上过拟合，反而伤真实场景。这个偏差应当**写进报告**，而不是被「修掉」。

### 11.5 冒烟暴露的两个发现（按治理约束：只记录，不据此调参）

**发现 A —— P1-A（相关性下限）是承重墙，不是理论担心。**

T001 的 `verify_reason` 原文：「题干考查企业会计基础，候选涉及信息质量、中期报告及政府会计，均不相关」→ 档位判 `none`，**但答案依然完整且正确**（权责发生制）。

这正是「none 档也必须给出完整解答」这条硬要求在真实链路上被观测到。修复轮之前 `relevant_indexes` 不存在，这 3 道 none 会被当成 similar、把跨章节的无关题当范例注入 prompt——答案质量会被噪声拖下去，而且**报表上看不出来**（档位显示 similar，像是命中了）。

**发现 B —— P1-B（内部标头泄漏）只修掉一半。**

完整标头 `【资料2｜例题｜知识点…｜第21章 租赁 · 第1节｜…】` 确实不再被抄进答案了，但模型改用 **`【资料1】`/`【资料2】`/`【资料4】` 当引用简写**，8 题里 **4 题**出现（T001/T002/T057/T058）。

说明 `MARKER_NOTICE` 挡住了「照抄标头」，没挡住「把标头编号当引用记号用」。这再次印证 §12 的教训：**提示词不是护栏**。真要根治得二选一——出流侧做确定性剥离（正则吃掉 `【资料N】`/`【题目N】` 短标），或在 prompt 里给出替代的引用写法（如「（教材第21章）」）。**本轮不动**，理由见 11.7。

### 11.6 语料缺口 vs 我们自己的检索失误（必须分开归因）

冒烟里几道新准则题答不好，第一反应容易全推给「语料没收录」。做了 4 次定向探测（`questions` 与 `textbook` 两个 collection）后，结论是**两种原因都有，且比例不同**：

- 语料统一是 `year: 2025`，**确实没有**：解释第19号、电子支付的终止确认条件、`Q20_CLI` 的分批（tranche）定义。
- 但**解释第18号实际是覆盖的**（经由「典例研习·12-7」），所以 T151/T316 答对了。我先前判断「18号也缺」是错的，在此更正。
- **T058 是我们自己的检索失误，不是语料缺口**：`ACC-2025-T-13-01-011`「解题高手」（`content_type=tip`，用关键词查 `score=1.0` 排第一）正文**逐字包含**金标准那句「债权人的索偿要求仅限于债务人的特定资产…企业需要对特定的基础资产或其现金流量进行评估（即穿透）」。但用题干原文做向量检索时它没进 top-5。→ 缺口在**召回**，不在语料。

**规模量化**：`新准则=是` 共 **68/400（17%）**；题干含 解释第19号/合同挂钩/无追索权/电子支付/穿透/SPPI 的共 **30 题（7.5%）**，题号 T031、T057–T059、T091、T092、T109、T111、T113–T116、T176、T178、T299、T300、T320、T324–T331、T383、T386–T389。比早先 13–15% 的粗估更紧。

导出文件的「汇总」表专门放了**「最新准则/新口径 × 档位」交叉**，就是为这个归因准备的：新口径那批 none 档偏高属语料缺口，不能算 agent 能力问题；两类混在一个总准确率里，报告结论会是错的。

### 11.7 基准治理（用户已批，写死在这）

题库自带条款：**「锁定后禁止用于 Prompt、RAG、工作流或模型调参」「仅用于正式效果检验，不得用于 Agent 调参」**。执行细则三条：

2. **发现 A/B 与 11.6 的召回问题只记录不修**。若要修，修完必须**重跑一轮全新基准**，否则前后数字失去可比性——用同一份题既调参又报分，报出来的分数没有意义。

两条贯穿全轮的经验：

1. **提示词不是护栏**。P1-B 与 P1-D 都先试了「在 prompt 里交代」，但真正的修复都是补一道

   代码保证下限。
2. **「静默回退」是本轮 P0 的共同形态**。单价查不到 → `compute_cost()` 回退 0.0（P0-C/P0-D）；
   激活模型查不到 → `get_active_model()` 回退 `.env` 的幻影模型名（P0-A）。两处都「不报错」，
   于是问题在用量报表里完全隐形，只能靠端到端实测撞出来。同类设计里 KB 检索失败降级为大模型
   直答也是「不报错」的——它能被看见，靠的是末尾那三档标注（见 §6「没资料」三档不可合并）。
   新增回退分支时要问一句：**这个回退会不会让某笔真实开销或某个真实失败变得不可见**；
   会的话就得配一条 WARNING、一个启动自检，或一句学生看得见的标注。
   （对照：OCR 失败原先也走「静默降级为纯文字提问」，本轮之前已改为直接 400 不落库不扣配额。）

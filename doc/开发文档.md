## 一、项目概述

### 1.1 项目目标

构建一个面向会计专业学生的智能答疑系统，基于通义千问大模型 + Function Calling 对接机器A 外部知识库检索服务，提供准确的会计专业问题解答。

### 1.2 核心功能

- 学生登录身份识别（学号+密码）
- AI 对话答疑（流式输出，支持多轮对话记忆）；大模型通过 Function Calling 自主决定是否检索知识库
- 科目选择（枚举由知识库侧维护，当前仅 CPA 会计）
- 管理员后台（学生管理、大模型管理、使用统计）

### 1.3 技术选型

| 层级 | 技术 | 版本 | 说明 |
|------|------|------|------|
| 前端框架 | Next.js (App Router) | 16.2.10 | React 全栈框架 |
| UI 库 | React | 19.2.4 | — |
| 前端样式 | Tailwind CSS | v4 | 原子化 CSS |
| 后端框架 | Python FastAPI | 0.115.* | 异步高性能 Web 框架 |
| 关系数据库 | MySQL 8.4（机器A，utf8mb4） | 8.4 | PyMySQL(DictCursor) 连接，开发直连公网、生产走私网 |
| 知识库检索 | 外部检索服务 `POST /kb/search` | — | httpx 客户端（`app/kb/client.py`），Function Calling 触发 |
| 大模型 | 通义千问 + DeepSeek | dashscope SDK 1.20.* | 对话生成（Function Calling），可在后台配置/切换 |
| 认证方案 | JWT | python-jose | 无状态令牌认证 |
| 密码加密 | bcrypt | passlib | 安全哈希 |
| 虚拟环境 | uv | 最新 | Python 3.11+ 包管理与虚拟环境 |

> DeepSeek（deepseek-v3/r1）走**阿里百炼统一接入**，复用 `DASHSCOPE_API_KEY`，模型名直接通过 dashscope `Generation.call` 调用，无需独立 SDK 或分支。

## 二、开发环境规范

### 2.1 uv 虚拟环境管理

**规则：所有后端开发和包安装必须严格在 uv 管理的虚拟环境中进行。**

#### 初始化步骤

```bash
# 进入后端目录
cd d:\code\answer\backend

# 用 uv 初始化 Python 项目
uv init --python 3.11

# 创建虚拟环境 (.venv 目录)
uv venv

# 激活虚拟环境 (Windows PowerShell)
.\.venv\Scripts\Activate.ps1

# 安装依赖
uv pip install -r requirements.txt

# 添加新依赖
uv pip install <package_name>
uv pip freeze > requirements.txt
```

#### 运行规范

```bash
# 启动后端 (通过 uv run)
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 运行脚本
uv run python seed.py
```

- `.venv/` 目录加入 `.gitignore`
- `pyproject.toml` + `uv.lock` 纳入版本控制
- `requirements.txt` 作为辅助导出文件

### 2.2 前端环境

## 三、端口规划

| 端口 | 服务 | 协议 | 传输数据 |
|------|------|------|----------|
| 8000 | FastAPI 后端 | HTTP/REST | JWT 认证、学生 CRUD、对话 CRUD、大模型管理、科目列表 |
| 8000 | FastAPI 后端 | HTTP/SSE | 对话流式接口，用户提问 → AI 逐块回答 |
| 3000 | Next.js 前端 | HTTP | 页面渲染、静态资源 |
| 3306 | 机器A MySQL 8.4 | TCP | 开发直连公网 `8.134.97.196`、生产走私网 `172.22.207.228` |
| 8100 | 机器A 知识库检索服务 | HTTP | `POST /kb/search`（仅私网暴露） |
| 443 | 通义千问对话 API | HTTPS | API Key + 上下文 → 生成文本 |

### 数据流向

```
浏览器 (localhost:3000)
  │
  ├─ HTTP REST ──→ FastAPI (localhost:8000)
  │                  ├─ MySQL 8.4  → 机器A:3306（开发公网 / 生产私网）
  │                  ├─ HTTP:8100  → 机器A 知识库检索服务 POST /kb/search
  │                  └─ HTTPS:443  → dashscope.aliyuncs.com（大模型 Function Calling）
  │
  └─ HTTP SSE ───→ FastAPI (localhost:8000/api/chat)
                    流式逐块返回 AI 回答（含 kb_search/kp_ids 事件）
```

## 四、数据库设计

### 4.1 表结构 (MySQL 8.4)

机器A MySQL（InnoDB / utf8mb4），启动时 `init_db()` 自动 `CREATE DATABASE IF NOT EXISTS` + 建 5 张表。连接配置见 `backend/.env`。

#### users 表（用户）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | PRIMARY KEY AUTO_INCREMENT | 用户 ID |
| student_id | VARCHAR(64) | UNIQUE NOT NULL | 学号（登录账号） |
| password_hash | VARCHAR(255) | NOT NULL | bcrypt 加密密码 |
| name | VARCHAR(64) | NOT NULL | 姓名 |
| role | VARCHAR(16) | DEFAULT 'student' | 角色：student / admin |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

#### conversations 表（对话）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | PRIMARY KEY AUTO_INCREMENT | 对话 ID |
| user_id | INT | NOT NULL | 所属用户 |
| title | VARCHAR(255) | DEFAULT '新对话' | 对话标题 |
| subject | VARCHAR(32) | NULL | 科目枚举值（如 `cpa_acc`） |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

#### messages 表（消息）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | PRIMARY KEY AUTO_INCREMENT | 消息 ID |
| conversation_id | INT | NOT NULL | 所属对话 |
| role | VARCHAR(16) | NOT NULL | 消息角色：user / assistant |
| content | MEDIUMTEXT | NOT NULL | 消息内容 |
| knowledge_point_ids | TEXT | NULL | KB 命中知识点编号 JSON 数组 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

#### 其余表

完整字段以 `app/database.py` 建表 SQL 为准，概览见 [`AGENTS.md` §7](../AGENTS.md#7-数据库表结构)。**无 `subjects` 表**（科目改为知识库侧枚举）。

| 表 | 用途 | 关键列 |
|----|------|--------|
| `model_configs` | 大模型配置 | `provider, model_name(UNIQUE), price_in, price_out, enabled, is_active` |
| `usage_logs` | 用量与费用 | `model_name, prompt_tokens, completion_tokens, total_tokens, cost` |

### 4.2 建表 SQL

完整建表语句见 `app/database.py::TABLES_SQL`（MySQL 8.x / InnoDB / utf8mb4 / `AUTO_INCREMENT` / `DATETIME DEFAULT CURRENT_TIMESTAMP`）。不迁移旧 SQLite 数据，MySQL 为全新库，首次 `seed.py` 写入管理员 + 默认模型。

### 5.3 核心模块说明

#### 5.3.1 main.py - FastAPI 入口

- 创建 FastAPI 应用实例
- 配置 CORS 中间件（允许前端 3000 端口跨域）
- 注册 5 个路由模块：auth、chat、admin、llm、kb.subjects
- 启动时调用 database.py 自动建库建表

#### 5.3.2 config.py - 配置管理

- 使用 `pydantic-settings` 读取 `.env` 文件
- 定义 `Settings` 类，包含 `MYSQL_*` / `KB_*` 等配置项
- 通过 `@lru_cache` 缓存配置单例

#### 5.3.3 database.py - 数据库

- 使用 `PyMySQL` + `DictCursor` 连接机器A MySQL 8.4
- `DB` 包装类保留 `db.execute()` 习惯，降低迁移面
- `get_db()`（FastAPI 依赖生成器）vs `get_db_ctx()`（脚本上下文管理器）
- `init_db()` 启动时 `CREATE DATABASE IF NOT EXISTS` + 建 5 张表

#### 5.3.4 models.py - 数据模型 (Pydantic)

```python
# 认证相关
class LoginRequest:          # 登录请求
    student_id: str
    password: str

class TokenResponse:         # 登录响应
    access_token: str
    token_type: str = "bearer"
    role: str

class UserInfo:              # 用户信息
    id: int
    student_id: str
    name: str
    role: str
    created_at: str

# 对话相关
class ConversationCreate:    # 新建对话
    title: str = "新对话"

class ConversationOut:       # 对话列表项
    id: int
    title: str
    subject: str | None
    created_at: str

class MessageOut:            # 消息输出
    id: int
    role: str
    content: str
    created_at: str

class ChatRequest:           # 对话请求
    conversation_id: int | None = None
    message: str
    subject: str | None = None   # 科目枚举，默认 cpa_acc

# 科目相关
class SubjectItem:           # 科目项（GET /api/subjects）
    subject: str
    name: str
    status: str

# 管理员相关
class StudentCreate:         # 创建学生
    student_id: str
    name: str
    password: str

class StudentUpdate:         # 修改学生
    name: str | None = None

class StatsResponse:         # 统计数据
    total_students: int
    total_conversations: int
    today_active_users: int
```

### 8.2 生产环境

- **后端**：应用服务器 B（`8.148.219.179`）运行 uvicorn（推荐 systemd 管理），走私网访问机器A MySQL/知识库

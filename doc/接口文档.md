## 一、通用约定

### 1.1 认证方式

所有需要认证的接口，请求时必须在 Header 中携带 JWT Token：

```
Authorization: Bearer <token>
```

- Token 通过 `POST /api/auth/login` 获取
- Token 有效期 24 小时，过期后需重新登录
- 管理员接口额外校验 `role=admin`，普通学生无权访问

### 1.2 请求格式

- 除文件上传外，所有请求体使用 `Content-Type: application/json`
- 文件上传使用 `Content-Type: multipart/form-data`

### 1.3 统一响应格式

**成功响应：** 直接返回业务数据（无外层包裹）

```json
// 单个对象
{ "id": 1, "name": "张三", ... }

// 列表
[{ "id": 1, ... }, { "id": 2, ... }]

// 分页列表
{
  "items": [{ "id": 1, ... }],
  "total": 50,
  "page": 1,
  "size": 20
}

// 操作成功（无返回数据时）
{ "message": "ok" }
```

**错误响应：** 统一返回以下格式

```json
{
  "detail": "错误描述信息"
}
```

### 1.4 HTTP 状态码

| 状态码 | 含义 | 使用场景 |
|--------|------|----------|
| 200 | 成功 | 正常请求 |
| 201 | 创建成功 | 新建资源 |
| 400 | 请求参数错误 | 参数校验失败、文件格式错误 |
| 401 | 未认证 | Token 缺失、过期或无效 |
| 403 | 无权限 | 非管理员访问管理接口 |
| 404 | 资源不存在 | 对话/学生/文档不存在 |
| 429 | 请求过于频繁 | `POST /api/chat`：每日配额用尽 / 上一条回答未完成 / 排队队列已满（v4.0 M1，文案区分见 [2.2](#22-对话模块)） |
| 500 | 服务器内部错误 | AI 模型调用失败、数据库异常 |

### 2.2 对话模块

#### POST `/api/chat` - 发送消息（SSE 流式）

> 需要认证：JWT

这是系统最核心的接口，使用 **Server-Sent Events (SSE)** 协议实现流式输出。

**请求：**
```
POST /api/chat
Content-Type: application/json
Authorization: Bearer <token>
```

```json
{
  "conversation_id": 3,
  "message": "什么是借贷记账法？",
  "subject": "cpa_acc"
}
```

- `conversation_id` 为 `null` 时，后端自动新建对话
- `conversation_id` 有值时，消息追加到该对话中
- `subject` 为科目枚举（取自 `GET /api/subjects`）；缺省或非法时后端回退默认 `cpa_acc`。后端据此注入知识库检索的 `subject`（模型不参与决定）

**请求前置校验（v4.0 M1，按顺序执行，任一不过直接返回 HTTP 429，不进入 SSE 流）：**

1. **配额校验**：当日提问数（当天 `role='user'` 消息数）≥ 生效上限（users 覆盖值 `daily_question_limit`，NULL 时跟随全局默认 `daily_question_limit_default`）；
2. **单人串行**：同一用户上一条回答未完成时拒绝重复提问；
3. **并发闸门**：全局同时对话数达 `chat_concurrency` 上限且排队人数已满 `chat_queue_size` 时拒绝；未满则进入排队（SSE 下发 `queue` 事件报队位）。

**429 错误响应（文案区分三种情形）：**
```json
{ "detail": "今日提问次数已用完（20/20），明天再来吧" }   // 配额用尽
{ "detail": "上一条回答还在进行中" }                        // 单人串行冲突
{ "detail": "当前提问人数较多，请稍后再试" }                // 排队队列已满
```

**SSE 响应格式：**

响应的 `Content-Type` 为 `text/event-stream`，数据按以下格式逐块推送：

```
data: {"type": "start", "conversation_id": 3}

data: {"type": "queue", "position": 2}

data: {"type": "kb_search"}

data: {"type": "kp_ids", "kp_ids": ["ACC-03-02-01", "ACC-03-02-02"]}

data: {"type": "kb_refs", "refs": [{"kp_id": "ACC-03-02-01", "chapter": "第三章", "title": "借贷记账法", "snippet": "content 前 100 字符…"}]}

data: {"type": "delta", "content": "借贷"}

data: {"type": "delta", "content": "记账法是一种复式记账方法..."}

data: {"type": "suggestions", "items": ["借贷记账法的记账规则？", "试算平衡怎么做？", "举个分录例子？"]}

data: {"type": "done", "message_id": 42}

```

**SSE 事件类型说明（v4.0 全集，标 ✦ 为 M1 新增）：**

| type | 含义 | 字段 | 触发时机与说明 |
|------|------|------|------|
| `start` | 流开始 | `conversation_id` | 返回对话 ID（新建对话时前端据此更新 URL/列表） |
| `queue` ✦ | 排队队位 | `position` | 并发闸门已满需排队时：入队推一次，此后每前进一位再推一次；无需排队则不出现 |
| `kb_search` | 开始检索 | — | 模型触发知识库检索时推送，前端可提示「正在检索知识库…」 |
| `kp_ids` | 知识点编号 | `kp_ids` | KB 命中知识点编号汇总（字符串数组，同时随回答落库）；检索无命中时不推送 |
| `kb_refs` ✦ | 引用卡片 | `refs` | 检索命中后推送；每项含 `kp_id`/`chapter`/`title`/`snippet`（content 前 100 字符），前端渲染为可展开卡片 |
| `delta` | 内容片段 | `content` | AI 回答的一小段文本，前端逐块追加显示 |
| `suggestions` ✦ | 追问建议 | `items` | 正文结束后、`done` 之前推送（最多 3 条）；模型未输出或解析失败时静默不发，不影响正文 |
| `done` | 流结束 | `message_id` | 完整回答已保存的消息 ID（可用于 `POST /api/feedback` 评价；回答内容为空时为 0） |
| `error` | 错误 | `detail` | 出错信息（如 AI 模型调用失败） |

> **解析契约**：SSE 的 `type` 字段枚举后续可能扩展，客户端必须按「已知类型处理、未知类型忽略」的方式解析，不得对未知 `type` 报错。

> 知识库检索失败（超时/5001 重试 1 次仍失败）时自动降级为大模型直答，不报错；此时无 `kp_ids`/`kb_refs` 事件。降级话术分档附在答案尾部随正文下发并落库（v4.0 M1）：检索服务不可用 →「⚠️ 知识库暂时不可用，本回答未经教材核对」；检索成功但空结果 →「知识库中未检索到直接相关内容」。

**错误事件：**
```
data: {"type": "error", "detail": "AI 模型调用超时，请稍后重试"}

```

**前端调用（核心逻辑，完整实现见 `frontend/src/lib/sse.ts`）：**
```typescript
async function sendChatMessage(
  conversationId: number | null,
  message: string,
  subject: string | null,
  onChunk: (text: string) => void,
  onStart: (convId: number) => void,
  onDone: (messageId: number) => void,
  onKbSearch?: () => void,
  onKpIds?: (kpIds: string[]) => void
) {
  const res = await fetch(`${API_BASE}/api/chat`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`
    },
    body: JSON.stringify({ conversation_id: conversationId, message, subject })
  });

  const reader = res.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() || '';

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.slice(6));
        switch (data.type) {
          case 'start':
            onStart(data.conversation_id);
            break;
          case 'kb_search':
            onKbSearch?.();  // 提示「正在检索知识库…」
            break;
          case 'kp_ids':
            onKpIds?.(data.kp_ids);
            break;
          case 'delta':
            onChunk(data.content);  // 逐块追加到消息区
            break;
          case 'done':
            onDone(data.message_id);
            break;
          case 'error':
            console.error(data.detail);
            break;
        }
      }
    }
  }
}
```

#### POST `/api/feedback` - 提交答案反馈（v4.0 M1 新增）

> 需要认证：JWT（全员可用）

对一条 AI 回答消息点赞/点踩；同一消息重复提交时覆盖更新（UPSERT 语义）。

**请求：**
```
POST /api/feedback
Content-Type: application/json
Authorization: Bearer <token>
```

```json
{
  "message_id": 42,
  "rating": "down",
  "reason": "分录方向讲反了"
}
```

- `rating` 仅支持 `up` / `down`；`rating=down` 时 `reason` 必填（`up` 时可省）
- `message_id` 取自 SSE `done` 事件或 `GET /api/conversations/{id}` 消息列表

**成功响应：** `200 OK`
```json
{ "message": "ok" }
```

**错误响应：**
- `400` - rating 非法
```json
{ "detail": "rating 仅支持 up / down" }
```
- `400` - 点踩未填理由
```json
{ "detail": "点踩时请填写理由" }
```
- `400` - 评价对象非 AI 回答

## 三、前后端联调指南

### 3.1 前端 API 封装层 (`lib/api.ts`)

所有请求统一通过 `apiFetch` 函数发送，自动处理：
- 附加 JWT Token 到 Header
- 401 响应时自动清除本地 Token 并跳转登录页
- JSON 请求/响应自动序列化

```typescript
const API_BASE = process.env.NEXT_PUBLIC_API_URL; // http://localhost:8000

async function apiFetch(path: string, options: RequestInit = {}): Promise<Response> {
  const token = localStorage.getItem('token');
  
  const res = await fetch(`${API_BASE}${path}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      'Authorization': token ? `Bearer ${token}` : '',
      ...options.headers,
    },
  });

  if (res.status === 401) {
    localStorage.removeItem('token');
    window.location.href = '/login';
    throw new Error('登录已过期');
  }

  if (!res.ok) {
    const error = await res.json();
    throw new Error(error.detail || '请求失败');
  }

  return res;
}
```

### 3.2 联调环境配置

**后端 CORS 配置（`main.py`）：**
```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],  # 前端地址
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**前端环境变量（`.env.local`）：**
```
NEXT_PUBLIC_API_URL=http://localhost:8000
```

### 3.3 SSE 流式对话联调要点

1. **不能用 `apiFetch`**：SSE 接口需要手动使用 `fetch` + `ReadableStream`
2. **不要设置 `Content-Type` 请求头**：SSE 响应为 `text/event-stream`
3. **Nginx 代理注意**：需关闭 buffer，配置 `proxy_buffering off`
4. **超时处理**：AI 回答可能耗时 10-30 秒，前端需设置合理的 fetch 超时或禁用超时
5. **中断机制**：用户点击"停止生成"时，调用 `AbortController.abort()` 中断连接

### 3.4 联调检查清单

| 检查项 | 前端 | 后端 |
|--------|------|------|
| 登录获取 Token | POST /api/auth/login 存 localStorage | 返回 JWT，bcrypt 校验密码 |
| Token 自动附加 | apiFetch 自动加 Authorization | deps.py 解析 JWT |
| Token 过期处理 | 401 → 清 Token → 跳登录页 | JWT 过期返回 401 |
| 对话列表加载 | GET /api/conversations 渲染左侧栏 | 返回当前用户对话，降序 |
| 流式对话 | POST /api/chat → SSE 逐块渲染 | StreamingResponse + yield |
| 新建对话 | conversation_id=null 自动创建 | start 事件返回 conversation_id |
| 消息历史 | 点击对话 → GET 消息列表渲染 | 升序返回，role 区分显示 |
| 删除对话 | DELETE → 移除列表项 | 级联删除消息 |
| 文件上传 | FormData + fetch（非 apiFetch） | multipart 解析 + 校验 |
| 管理员权限 | 非 admin 隐藏管理入口 | role != admin 返回 403 |
| 批量导入 | 上传 Excel + 显示结果 | 解析 openpyxl，逐行校验 |

建议按以下顺序逐步联调，确保每步稳定后再进行下一步：

### 4.1 大模型管理（仅管理员）

所有接口前缀 `/api/admin/models`，需 `role=admin`。

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 模型列表 | GET | `/api/admin/models` | 返回全部模型配置 |
| 用量与费用统计 | GET | `/api/admin/models/usage?days=7` | days 范围 1~90，默认 7 |
| 新增模型 | POST | `/api/admin/models` | model_name 唯一 |
| 修改模型 | PUT | `/api/admin/models/{id}` | 单价/名称/启用等 |
| 删除模型 | DELETE | `/api/admin/models/{id}` | |
| 设为当前模型 | POST | `/api/admin/models/{id}/activate` | 事务内其余置 0，目标置 1 |

**模型对象结构：**

```json
{
  "id": 1,
  "provider": "ali",           // 'ali' | 'deepseek'
  "model_name": "qwen-plus",   // dashscope 调用使用的模型标识
  "display_name": "通义千问 Plus",
  "price_in": 0.0008,           // 元/千 token（输入）
  "price_out": 0.002,           // 元/千 token（输出）
  "enabled": true,
  "is_active": false,           // 是否为当前使用模型
  "created_at": "..."
}
```

**新增/修改请求体：** `provider, model_name, display_name, price_in, price_out, enabled`（修改时字段均可选）。

**用量统计响应结构：**

```json
{
  "total_tokens": 12345,
  "total_cost": 1.2345,
  "today_tokens": 234,
  "today_cost": 0.0234,
  "by_model": [{ "model_name": "qwen-plus", "tokens": 12345, "cost": 1.2345 }],
  "daily": [{ "date": "2026-07-01", "tokens": 100, "cost": 0.01 }]  // 覆盖最近 days 天，无数据补 0
}
```

**费用计算：** `cost = 输入 tokens/1000 × price_in + 输出 tokens/1000 × price_out`。用量在 `/api/chat` 流式结束时，从 dashscope 响应的 `usage`（input/output tokens）自动记入 `usage_logs`。

### 4.2 科目列表

## 五、运维接口

#### GET `/api/health` - 健康检查（v4.0 M1 升级为三字段）

> 无需认证

逐项探测 MySQL 与知识库检索服务：

- **MySQL**：执行 `SELECT 1` 探测；
- **知识库**：优先 `GET {KB_BASE_URL}/health`（3s 超时）；该端点不存在（404）时降级为轻量 `POST /kb/search`（`top_k=1`，`query` 传固定词）探测。

**请求：**
```
GET /api/health
```

**成功响应：** `200 OK`（任一依赖 `fail` 时 `status=degraded`，HTTP 状态码仍为 200）
```json
{
  "status": "ok",
  "mysql": "ok",
  "kb": "ok"
}
```

```json
{
  "status": "degraded",
  "mysql": "ok",
  "kb": "fail"
}
```

| 字段 | 取值 | 说明 |
|------|------|------|
| `status` | `ok` / `degraded` | 两项依赖均 ok 时为 `ok`，否则 `degraded` |
| `mysql` | `ok` / `fail` | MySQL 连通性 |
| `kb` | `ok` / `fail` | 知识库检索服务连通性 |

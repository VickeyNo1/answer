# CPA 会计知识库 · 后端对接文档

> 版本：v1.0（2026-07）
> 面向：后端开发（对话服务 / Agent 编排方）
> 知识库侧联系人：知识库负责人
>
> 一句话：知识库对外只暴露 **1 个 HTTP 检索接口**。后端把它注册为大模型的 Function Calling 工具，由大模型决定何时调用；检索结果按约定格式拼进 prompt 让大模型作答。

---

## 0. 总体调用流程

```
用户提问
   │
   ▼
后端 → 大模型（携带 §2 的 tool schema）
   │
   ├─ 大模型判断【无需查资料】→ 直接回答，流程结束
   │
   └─ 大模型返回 tool_call: search_cpa_knowledge(query, collection, top_k)
          │
          ▼
      后端 HTTP 调用知识库检索接口（§1）
          │
          ▼
      后端把检索结果按 §3 格式拼成上下文，连同原问题再次发给大模型
          │
          ▼
      大模型生成最终答案（可标注依据的知识点编号）
```

知识库内部实现（阿里云 embedding + Qdrant + BM25 + RRF + Reranker）对后端完全透明；**后端不需要任何阿里云 API Key**。

## 1. 检索接口契约（唯一接口）

### 1.1 基本信息

| 项 | 值 |
|---|---|
| 方法 | `POST` |
| 路径 | `/kb/search` |
| Content-Type | `application/json; charset=utf-8` |
| 服务地址 | 生产：`http://172.22.207.228:8100`（机器A私网，机器B经VPC对等连接调用）；本机开发：`http://127.0.0.1:8100` |
| 鉴权 | Header `X-KB-Token: <token>`（token 由知识库侧提供；服务端未配置 KB_TOKEN 时可不带） |
| 超时建议 | 后端侧设 10s（含 embedding API 调用与重排，常规响应 1~3s） |

### 1.2 请求体

```json
{
  "query": "融资租赁和经营租赁怎么区分",
  "collection": "textbook",
  "top_k": 5
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 自然语言查询，建议 ≤200 字 |
| `collection` | string | 否 | `textbook`=教材讲解（默认），`questions`=练习题 |
| `top_k` | int | 否 | 返回条数，默认 5，上限 20 |

### 1.3 响应体 — collection = textbook（教材）

```json
{
  "code": 0,
  "collection": "textbook",
  "query": "融资租赁和经营租赁怎么区分",
  "results": [
    {
      "score": 0.87,
      "knowledge_point_ids": ["ACC-21-01-01"],
      "chunk_id": "ACC-21-S01-C003",
      "chapter_id": "ACC-21",
      "chapter": "第21章 租赁",
      "section_id": "ACC-21-01",
      "section": "第1节 租赁的识别",
      "title": "融资租赁的判断标准",
      "content_type": "theory",
      "content": "融资租赁是指实质上转移了与租赁资产所有权有关的几乎全部风险和报酬的租赁……"
    }
  ]
}
```

教材结果字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `score` | float | 相关度分数（重排后），仅用于排序，**不同请求间不可比** |
| `knowledge_point_ids` | string[] | ★ 知识点 ID 列表（可能为空数组），格式 `ACC-章-节-知识点`，是后续个性化归因的关键字段，**请原样透传/落库** |
| `chunk_id` | string | 教材片段唯一 ID |
| `chapter_id` / `chapter` | string | 章 ID / 章标题 |
| `section_id` / `section` | string | 节 ID / 节标题 |
| `title` | string | 片段小标题 |
| `content_type` | string | 片段类型：`theory` 理论 / `example` 例题 / `entry` 分录 / `table` 表格 / `formula` 公式 / `tip` 提示 / `faq` 问答 / `principle` 原则 |
| `content` | string | 正文（喂给大模型的主体，约 200~1400 字） |

### 1.4 响应体 — collection = questions（题库）

```json
{
  "code": 0,
  "collection": "questions",
  "query": "会计信息质量要求",
  "results": [
    {
      "score": 0.91,
      "knowledge_point_ids": ["ACC-01-03-01", "ACC-01-03-02"],
      "question_id": "Q-0012",
      "chapter_id": "ACC-01",
      "chapter": "第一章 总论",
      "question_type": "单选",
      "stem": "下列各项中，体现会计信息质量谨慎性要求的是（　）。",
      "options": {"A": "……", "B": "……", "C": "……", "D": "……"},
      "answer": "B",
      "explanation": "谨慎性要求企业……",
      "materials": null,
      "sub_questions": null
    }
  ]
}
```

题库结果字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `question_id` | string | 题目唯一 ID |
| `question_type` | string | `单选` / `多选` / `计算` / `综合` |
| `stem` | string \| null | 题干（客观题有；计算/综合题为 null，看 `materials`） |
| `options` | object \| null | 选项字典 `{A:..,B:..}`，仅客观题有 |
| `answer` | string \| null | 答案，如 `"B"`、`"ABD"` |
| `explanation` | string \| null | 解析（约 69 题原始资料缺失，为空或标注"(原始资料缺失)"） |
| `materials` | string \| null | 题目资料，仅计算/综合题有 |
| `sub_questions` | array \| null | 子问列表，仅计算/综合题有 |
| 其余字段 | — | 同教材：`score` / `knowledge_point_ids` / `chapter_id` / `chapter` |

### 1.5 错误响应

```json
{ "code": 4001, "message": "query 不能为空", "results": [] }
```

| code | HTTP | 含义 | 后端处理建议 |
|---|---|---|---|
| 0 | 200 | 成功（`results` 可能为空数组=没检索到） | 空结果时让大模型直接回答并说明"知识库未检索到" |
| 4001 | 400 | 参数错误 | 修正请求 |
| 5001 | 500 | 内部错误（embedding API 失败/索引异常） | 重试 1 次，仍失败则降级为大模型直答 |
| — | 超时 | 网络/服务无响应 | 同上降级 |

## 2. 大模型工具定义（Function Calling schema）

后端把下面的 tool 注册给大模型（Qwen / OpenAI 兼容格式均可用），由大模型自行决定是否调用及传参：

```json
{
  "type": "function",
  "function": {
    "name": "search_cpa_knowledge",
    "description": "检索CPA会计知识库。当用户问题涉及会计准则、会计概念、账务处理、会计分录、例题讲解，或需要教材原文/练习题佐证时调用；用户想要练习题、真题时用 collection=questions；闲聊或与会计无关的问题不要调用。",
    "parameters": {
      "type": "object",
      "properties": {
        "query": {
          "type": "string",
          "description": "用自然语言描述要查什么，尽量保留用户问题中的专业词"
        },
        "collection": {
          "type": "string",
          "enum": ["textbook", "questions"],
          "description": "textbook=查教材讲解（默认）；questions=查练习题/真题"
        },
        "top_k": {
          "type": "integer",
          "description": "返回条数，默认5"
        }
      },
      "required": ["query"]
    }
  }
}
```

大模型返回 `tool_call` 后，后端将其 `arguments` 原样映射为 §1.2 的请求体调用 `/kb/search`。

## 3. 检索结果拼接格式（喂回大模型）

后端拿到 `results` 后，拼成如下上下文，作为 tool 结果（或 system/user 消息）回传给大模型：

**教材（textbook）：**

```
以下是从CPA会计知识库检索到的资料，请据此回答用户问题，并标注依据的知识点编号：

【资料1｜知识点 ACC-21-01-01｜第21章 租赁 · 第1节 租赁的识别｜融资租赁的判断标准】
融资租赁是指实质上转移了与租赁资产所有权有关的几乎全部风险和报酬的租赁……

【资料2｜知识点 ACC-21-01-02｜第21章 租赁 · 第1节 租赁的识别｜经营租赁的特征】
……
```

**题库（questions）：**

```
以下是从CPA题库检索到的题目：

【题目1｜Q-0012｜单选｜知识点 ACC-01-03-01】
题干：下列各项中，体现会计信息质量谨慎性要求的是（　）。
选项：A.…… B.…… C.…… D.……
答案：B
解析：谨慎性要求企业……
```

约定：
- `knowledge_point_ids` 为空时，标注为 `知识点 未标注`；
- 建议在 system prompt 中要求大模型"回答末尾列出所依据的知识点编号"——这些编号是后续做学生掌握度归因的钩子；
- 单条 `content` 已控制在 1400 字内，top_k=5 时上下文约 3~7k 字，主流模型均可容纳。

## 4. 知识点 ID（KP）体系说明

- 格式：`ACC-章-节-知识点`，如 `ACC-13-02-02`；共 **30 章 / 102 节 / 276 个知识点**；
- `ACC-XX-00-00` 为"第X章·通用知识"兜底 KP；
- 完整知识点树见知识库侧文件 `03_structured/knowledge_tree.json`（如后端需要展示知识点名称，可向知识库侧要一份该 JSON 或增加 `/kb/tree` 只读接口）；
- **强烈建议**后端在答疑/答题记录中落库 KP 字段，后续学生掌握度、薄弱环节分析全靠它串联。

## 5. 部署与联调约定

| 事项 | 约定 |
|---|---|
| 服务形态 | 知识库侧以 FastAPI 独立进程部署在**机器A（数据服务器）**，systemd 常驻，仅私网 8100 端口对机器B开放（安全组白名单 + X-KB-Token 双保险），不暴露公网；部署细节见 [部署指南-机器A.md](部署指南-机器A.md) |
| 依赖 | 仅知识库侧需要 `DASHSCOPE_API_KEY`（阿里云 embedding），后端无需任何密钥 |
| 性能参考 | 单次检索 1~3s（含云端 embedding + 本地重排）；QPS 要求高时再议缓存/扩容 |
| 数据规模 | 教材片段 1091 条、题目 606 道，均带 KP 元数据，1024 维语义向量 |
| 联调冒烟 | 服务起来后，后端用 §1.2 示例请求打 `/kb/search`，能返回带 `knowledge_point_ids` 的结果即通 |
| 变更约定 | 接口字段只增不改不删；新增字段后端应忽略未知字段 |

## 6. 联调 checklist（后端自查）

- [ ] tool schema 已注册，闲聊类问题大模型不触发检索
- [ ] `collection=textbook` / `questions` 两种请求均能拿到结果
- [ ] 空结果（`results: []`）时有降级话术，不报错
- [ ] 检索超时/5001 时降级为大模型直答
- [ ] 结果中的 `knowledge_point_ids` 已透传并落库（为个性化做准备）
- [ ] 大模型最终回答能标注知识点编号
